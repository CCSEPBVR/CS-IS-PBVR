# Client Tests

このディレクトリは、PBVR Client の QtTest を扱う。

## GUIテストの実行前確認

- GUIテストを起動する前に、ビルドログまたはビルド設定から実際の`.app`の出力先を特定し、その絶対パスが存在することを確認してから起動する。
- 推測した成果物パスや、過去のビルドで生成された別の`.app`を起動しない。

## 専用QtTestの依存整合性

- 専用QtTestを個別にビルドする場合、共有ヘッダとリンク対象の静的ライブラリが同じソース状態から生成されていることを確認する。
- 共有構造体、列挙型、仮想関数、Qt metatypeなどABIに影響する変更がある場合は、専用QtTestだけでなくClient依存ライブラリを先に再ビルドする。
- コンパイル成功後の即時SIGSEGVでは、ソース不具合に限定せず、共有ヘッダと静的ライブラリの生成時刻およびビルド状態を確認する。

## CSテストのサーバ管理

- 一連の最終CSテストは、新規に起動したサーバプロセスを使用する。起動したPIDと待受ポートを記録し、テスト前に接続可能であることを確認する。
- テスト終了後は、そのテストで起動したサーバだけを終了し、待受ポートが解放されたことを確認する。
- ObjectInfoなどの応答待ちがタイムアウトした場合、同じGUI操作を繰り返す前に、クライアントの接続状態、Local／CSモード、サーバプロセス、待受ポート、および双方のログを確認する。

## 成果物の検証

- テスト開始時刻と期待するケース・タイムステップの一覧を記録する。既存のスクリーンショットは、新しいテスト結果の証拠として数えない。
- 各スクリーンショットについて、今回のテスト開始後に作成または更新されたことと、対応するケース名・タイムステップが一致することを確認する。
- 最終結果は、QtTestログのPASS／FAIL、Markdownレポート、スクリーンショットの件数と対象、およびファイル更新時刻を相互に照合する。いずれかが一致しない場合は完了と報告しない。
